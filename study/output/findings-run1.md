## 2. Method and known biases (S-3)

- **Discovery.** GitHub code search, one query per target path × size band (10 targets × 4 bands = 40 slices), forks excluded, each slice paged until exhausted or the 1,000-result cap. Search returns a relevance-ranked slice, not the population: what lies past the cap is never seen.
- **Expansion.** Queued repositories were expanded in a seeded, stratified draw (plan §5, Expansion order): each draw went to the target with the fewest files so far, then to the size band least drawn relative to its search total, then to a hash-ordered repository in that band. Expansion reads the whole default-branch tree, so a repository drawn for one target contributes every target file it holds.
- **Balance is by design.** Because the draw equalizes targets, the file counts per target and the client mix (Q1, Q4) mostly reflect the quota, not how common each file type is. Search `total_count` per target (Q1) is the better signal of relative prevalence, with its own caveats.
- **Overshoot on multi-file targets.** Skills and Cursor rules come many to a repository, so one draw can add dozens of files; those targets end above their share.
- **Search-term requirement.** Each query needs a content term (`mcpServers`, `servers`, `permissions`, `description`, `claude`, `agents`, `copilot`), so a file lacking it is found only through another hit in its repository.
- **Default branch only**, and truncated trees can miss files. Stars and push dates are as of collection.
- **Deduplication (C-7).** Headline per-file figures use one file per normalized content hash (the redacted text with CRLF normalized), keeping the first collected. Raw figures are shown alongside and labeled. Owner-level figures count distinct owners.
- **Credential detection** is pattern-based only and nothing was validated against a live service (D-4). The `keyed-literal` detector flags any literal assigned to a key named like a secret, so some hits are likely placeholders or dummy values rather than real credentials (S-9).
- **No significance testing** (plan §7). Cross-band comparisons are descriptive.
